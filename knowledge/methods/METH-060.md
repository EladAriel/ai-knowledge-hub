# METH-060: Microsoft 'knowledge spine' practices checklist

## Summary

Only 3% of 200+ enterprises have a shared self-updating knowledge layer; four practices correlate with margin gains.

## Details

Practices: collect context centrally; turn every correction into a test case; use fixes to change agent behavior, not just one answer; a named owner settling conflicts and stale content. Correlation, mostly a rebrand. Devs: 'convert to test case' button/script on every thumbs-down trace; track corrections-to-tests per week.

## Content

**1. [Microsoft's "knowledge spine" study](https://www.microsoft.com/en-us/copilot/blog/2026/10/27/the-ai-advantage-your-company-can-keep/)** (Oct 27)
- **The finding:** Microsoft and Keystone studied more than 200 enterprises. Only 3% have the building blocks of a shared, self-updating knowledge layer for agents. Firms using more of the practices saw bigger margin gains, but the study says itself that this is correlation, not proof.
- **The four practices:**
  - Collect context in one central place.
  - Turn every correction into a test case.
  - Use those fixes to change how the agent behaves, not just that one answer.
  - Give the knowledge layer a named owner who settles conflicts and stale content.
- **Caveat:** it's mostly a rebrand of a shared knowledge base plus a feedback loop. It's still a useful checklist.
- Adopt for:
  - *Architects:* name one owner per source domain, who decides which source wins and when content expires.
  - *Product:* track how many corrections become tests each week, as a health metric.
  - *Devs:* add a "convert to test case" button or script on every thumbs-down trace.
