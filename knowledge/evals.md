# AI Evals

- [EVAL-001](evals/EVAL-001.md) | /claude-api build-eval + hillclimb | Build an eval inside the codebase from real traces, then improve the app one patch at a time against held-out cases.
- [EVAL-002](evals/EVAL-002.md) | RBC: Randomized Block Curation | A method to check which parts of the playbook the agent wrote for himself (like ACE or Dynamic Cheatsheet) really help.
- [EVAL-003](evals/EVAL-003.md) | Memory evals should check the store (FEB-30, Bemula) | Grading only final answers disagreed with checking the memory store by 16 points; no memory system passed forget requests above 1.5%.
- [EVAL-004](evals/EVAL-004.md) | Eval: golden question set + retrieval recall@k (with negative ACL cases) | Fixed real questions labeled with gold doc IDs; measure recall@5/@10, MRR and leak count per user in CI.
- [EVAL-005](evals/EVAL-005.md) | Same Context, Different Agents | Controlled research on three techniques of context engineering (the rest of the item is cut off in the transcript).
- [EVAL-006](evals/EVAL-006.md) | Jev Meets the Trolley Problem | 5,240 scenarios on 14 decision models, including Jev and GPT-6 Luna.
- [EVAL-007](evals/EVAL-007.md) | Eval: citation correctness (ALCE recall/precision) | For every claim, check the cited chunks support it: citation recall and citation precision.
- [EVAL-008](evals/EVAL-008.md) | FDE-Gym: The Last Mile of AI Delivery | Benchmark of 95 FDE tasks from 20 customer scenarios in 18 sectors.
- [EVAL-009](evals/EVAL-009.md) | CoverSynth: coverage-guided retrieval eval sets | Generate eval questions from your corpus covering different retrieval needs; human sets were too easy (91% vs 12% answered).
- [EVAL-010](evals/EVAL-010.md) | Eval: LLM-as-judge with yes/no rubric, calibrated before trust | Two yes/no judges (resolves the task? / rebuildable from cited snippets?) from a different model family, majority of 3, checked against human labels.
- [EVAL-011](evals/EVAL-011.md) | Harness-Delta Attribution (HDA) | An evaluation protocol that breaks down the improvement that automatic optimization of prompts, skills and tools produces into three parts.
- [EVAL-012](evals/EVAL-012.md) | MASIF: successful agent runs hide failures | 1,828 multi-agent traces: hidden failures in 54.3% of successful traces and 75.2% of failed ones.
- [EVAL-013](evals/EVAL-013.md) | Eval: regression suite from past production failures | Versioned cases, each a real failure; a change can't ship if a previously passing case fails.
- [EVAL-014](evals/EVAL-014.md) | Eval: unanswerable-question test (Correct Abstention Rate) | Mix in questions the docs can't answer and check the system declines; track CAR next to accuracy.
- [EVAL-015](evals/EVAL-015.md) | Eval: canary freshness and coverage test | Plant tagged test changes in real sources and time how long each takes to appear or disappear in search.
- [EVAL-016](evals/EVAL-016.md) | Eval: answer-span containment and chunk integrity | Check whether each gold answer span sits whole inside one chunk and in the retrieved top-k; lint fragments and broken tables.
- [EVAL-017](evals/EVAL-017.md) | Eval: extraction spot-check with drift rates | Precision/recall of extracted entities vs a small hand-labeled set, plus over-count, grounding, duplicate and deletion rates.
- [EVAL-018](evals/EVAL-018.md) | Eval: filtered index recall audit | Compare index results with exact brute-force top results, separately per filter scope.
- [EVAL-019](evals/EVAL-019.md) | SWE-Shift: Agents when the world shifts mid-mission | A benchmark where the code, dependencies, or requirements change while the agent is running.
- [EVAL-020](evals/EVAL-020.md) | Trajectory check with pressure cases (+ Log-To-Leak rule) | Evaluate what the agent actually did from the run log, not just the result; ~5 pressure tasks that push it to skip approval.
- [EVAL-021](evals/EVAL-021.md) | Decision models as cheap hallucination judges | Judges that return only a label + probability matched a large text judge on context contradictions and came within 3 points on factual errors.
- [EVAL-022](evals/EVAL-022.md) | Enterprise agent benchmark: agents trust Slack over systems of record | 19 models, 41 tasks on simulated Salesforce/Zendesk/Jira/Slack: 40% of runs broke a rule.
- [EVAL-023](evals/EVAL-023.md) | Eval: planted-conflict test (system of record vs Slack) | Plant false facts (some with instructions) in low-trust sources and check answers still follow the system of record.
- [EVAL-024](evals/EVAL-024.md) | Eval: pass^k (repeat-run consistency) | Run each golden question k times (e.g. 5) and count questions answered right on every run, not just once (idea from tau-bench).
- [EVAL-025](evals/EVAL-025.md) | Eval: old vs new index diff test (gate for an index/model switch) | Run the same queries on the old (v1) and new (v2) index, label only the queries where they disagree, and allow the switch only if golden recall, win rate and threshold pass-rate all hold.
- [EVAL-026](evals/EVAL-026.md) | Aligned RAG Evaluation: ASR hides failures created by the defenses | In RAG-poisoning evaluations, the attack-success-rate (ASR) metric hides failures that the defenses themselves introduce.
- [EVAL-027](evals/EVAL-027.md) | Eval: context faithfulness with edited docs (counterfactual facts + version conflicts) | Copy each doc, change its key fact to a believable fake value, run the question with the edited doc in context, and score with code: pass if the answer has the fake value, fail if it has the original.
- [EVAL-028](evals/EVAL-028.md) | RAGLog: find which RAG stage broke, using only logs (reference-free fault localization) | A logging proxy records the pipeline's API calls, maps them to stages (rewrite, embed, retrieve, rerank, generate) and says which stage failed; no reference answers, no code changes.
- [EVAL-029](evals/EVAL-029.md) | Eval: context order test (lost-in-the-middle sensitivity to chunk position) | Check whether the answer changes depending on where the right chunk sits in the context. Models tend to use facts at the start and end better than in the middle (Lost in the Middle).
- [EVAL-030](evals/EVAL-030.md) | Eval: duplicate crowding and repeat syncs | Checks that copies of the same document (Drive, Confluence, an email attachment) don't take several top results, and that running a sync twice creates no extra copies. Under a day; becomes a CI test.
- [EVAL-031](evals/EVAL-031.md) | MaxxBench: perturbed-requirement benchmark that catches 'benchmaxxing' | 89 DeepSWE tasks with small requirement changes (median 17 lines), e.g. lowercase filenames or UTC timestamps, to test whether the agent does what the prompt says or what it guesses hidden tests want. Trajectory analysis: models understand the new requirement yet revert to the original behavior (~25% of failures for Opus 5 and GLM-5.3). Recommendation: Adopt as an eval method.
- [EVAL-032](evals/EVAL-032.md) | g-harness-evals (Garry Tan): same model across 7 harnesses | Holds the model (Opus 5.5 or GPT-6.1 Sol) and 20 tasks fixed and swaps only the harness (Claude Code, Codex, Hermes, OpenClaw, QM), measuring success rate, cost per solved task and time. Success rates 71-79% are statistically indistinguishable, but cost differs ~2x ($0.19-$0.44 per task on Opus).
- [EVAL-033](evals/EVAL-033.md) | Eval: schema and number checks (disposition + citations + numbers) | Force every answer into a schema and score it with code. New in the eval rotation on Nov 6.
- [EVAL-034](evals/EVAL-034.md) | Eval: memory overreach test (low-stakes notes → high-stakes tasks) | Let the agent form memories in low-stakes sessions, then check how often they wrongly carry into high-stakes tasks. New in the eval rotation on Nov 7.
- [EVAL-035](evals/EVAL-035.md) | Eval: cost and latency per correct answer | Run the same golden set through 2–4 setups and compare cost per correct answer (not just accuracy)—e.g. search only, wiki only, search+wiki, cheaper model.
- [EVAL-036](evals/EVAL-036.md) | Eval: parsing accuracy scorecard (facts kept, before any search) | A small hand-labeled test of whether the parser kept the facts, before any search happens. New in the eval rotation on Nov 10.
- [EVAL-037](evals/EVAL-037.md) | Eval: merge audit for entity resolution | A check on whether you joined the right records. The Oct 24 check asked whether entities were found at all. This one asks whether matches were merged correctly. New in the eval rotation on Nov 11.
