# AI Pipelines

- [PIPE-001](pipelines/PIPE-001.md) | Reliable scheduled agent automations (bookmarks + ledger) | Scheduled briefs lie with fixed 24h windows and silent source failures; use per-source bookmarks, a ledger and re-checks.
- [PIPE-002](pipelines/PIPE-002.md) | Claude Code team's layered code review | Stack automated checks so humans spend attention only where risk is; merged PRs doubled while revert rate fell >40%.
- [PIPE-003](pipelines/PIPE-003.md) | Pipeline: permission-aware retrieval (ACL) | Source ACLs + identity crawl -> ACL fields on every chunk -> identity at query time -> pre/post-filter -> only authorized chunks reach the LLM -> re-check at action time + audit.
- [PIPE-004](pipelines/PIPE-004.md) | Pipeline: retrieval and reranking | query -> optional rewrite/split -> ACL pre-filter -> BM25 + vector (top 100-200) -> RRF (k=60) -> rerank to ~15 -> expand to parent section -> compress/token budget -> agent.
- [PIPE-005](pipelines/PIPE-005.md) | Pipeline: agent and answer layer | question + identity -> plan sub-queries -> hybrid search over a navigation layer -> fetch sources -> draft -> validate in code (exact quotes, schema, ACL) -> search again if evidence missing -> cite or decline and log a content gap.
- [PIPE-006](pipelines/PIPE-006.md) | Pipeline: feedback and monitoring loop | capture (traces, feedback, incidents) -> score every trace cheaply -> group failures, rank by frequency x severity -> fix -> freeze as regression case -> CI gate -> watch release -> capture.
- [PIPE-007](pipelines/PIPE-007.md) | Pipeline: end-to-end company brain | connectors with permissions -> parse with doc metadata -> enrich against reviewed ontology -> index (vector+keyword+graph) -> query-time permissions as user -> tiered retrieval -> line-level citations or decline -> session log -> offline memory cleanup.
- [PIPE-008](pipelines/PIPE-008.md) | Pipeline: ingestion and connectors | change webhook (hint) -> delta pull (source of truth) -> fetch content, ACL, metadata -> stable doc ID + content hash -> idempotent upsert or tombstone -> reconcile.
- [PIPE-009](pipelines/PIPE-009.md) | Pipeline: parsing and chunking | raw file -> route (text layer or vision parser) -> typed blocks with page, bbox, reading order -> structure-aware chunks -> add context -> hash and embed -> index with doc-identity metadata.
- [PIPE-010](pipelines/PIPE-010.md) | Pipeline: enrichment (extraction + entity resolution) | chunk -> extract against typed schema -> link each value to source position -> drop out-of-schema items -> resolve duplicates -> human review for low confidence -> write with entity->chunk link -> index.
- [PIPE-011](pipelines/PIPE-011.md) | Pipeline: indexing with alias switch and rollback | chunks + metadata (doc_id, version, acl, embed_model) -> versioned store -> build vector/BM25/graph into a NEW index -> recall audit -> switch alias -> keep old index for rollback.
- [PIPE-012](pipelines/PIPE-012.md) | Pipeline: permissions and ACLs (fail-closed) | verified token -> groups lookup (deny on failure) -> permission engine returns allowed IDs/filter -> filtered hybrid search -> live recheck of top hits -> rerank -> LLM -> answer inherits strictest sensitivity label -> per-permission-set cache/memory -> audit.
- [PIPE-013](pipelines/PIPE-013.md) | Pipeline: retrieval + calibrated reranking | query -> optional rewrite -> permission-filtered BM25 + vector (top 50-100 each) -> RRF -> cross-encoder rerank -> keep above calibrated threshold or 'I don't know' -> pick passages -> answer.
- [PIPE-014](pipelines/PIPE-014.md) | Pipeline: gated agent/answer layer with code checks | question -> gate (answer/clarify/decline) -> template or retrieval -> pack evidence -> grounded generation with citations -> code checks -> confirm before writes -> response + trace.
- [PIPE-015](pipelines/PIPE-015.md) | Pipeline: feedback & monitoring v2 (log what the model saw) + unsupported-claim monitor | record full trace incl. final context -> cheap live judges/rules -> route feedback by failure type -> find failed stage -> fix -> regression set -> CI -> confirm live.
- [PIPE-016](pipelines/PIPE-016.md) | Pipeline: end-to-end with question-type routing | sources -> permission-carrying incremental connectors -> parse + contextualize -> entity IDs + version links -> keyword/vector/graph index (links keep source IDs) -> permission filter -> route: lookups to hybrid+rerank, multi-source to wiki/graph, counting to SQL -> cited answer or decline -> feedback to eval set.
- [PIPE-017](pipelines/PIPE-017.md) | Pipeline: ingestion contracts and trust tiers | source API -> managed login/proxy -> connector emits standard record -> schema check (accept/freeze/quarantine) -> raw store -> lineage event -> parse and index.
- [PIPE-018](pipelines/PIPE-018.md) | Pipeline: parsing and chunking (heading-aware) | raw file -> parse with layout, reading order and element positions -> check a sample against original pages -> split at headings -> group paragraphs into chunks per section -> prepend heading path -> index with page and position.
- [PIPE-019](pipelines/PIPE-019.md) | Pipeline: enrichment with three-way entity resolution | Extract entities against a schema (GLiNER first, LLM only for what's left), normalize + alias check, vector-search candidates of the same type, score, then merge / send to review / create new; tag against a fixed taxonomy; publish to index and graph.
- [PIPE-020](pipelines/PIPE-020.md) | Pipeline: embedding model upgrade as an index migration | Treat an embedding-model change as a schema migration: new versioned index or vector field, dual-write, backfill from source text, shadow-test, gradual traffic shift, keep the old index for rollback.
- [PIPE-021](pipelines/PIPE-021.md) | Pipeline: permissions for derived knowledge and agent identity | sync permissions -> permission filter in the index -> live recheck of top results at the source -> redact sensitive fields -> audit log.
- [PIPE-022](pipelines/PIPE-022.md) | Pipeline: retrieval and reranking with a flexible budget | question -> hybrid keyword+vector search -> top N candidates -> cross-encoder rerank -> drop under a minimum score -> pass top k in order to the LLM.
- [PIPE-023](pipelines/PIPE-023.md) | Pipeline: event-driven ingestion with page hashes, resume and a completion marker | Third pass on ingestion and connectors: change event -> priority queue -> did the document change? -> which pages/chunks changed? -> embed only those -> save -> mark the document complete -> searchable. Events not polling, idempotent syncs, completion marker, freshness measured per source.
- [PIPE-024](pipelines/PIPE-024.md) | Pipeline: the answer layer (structured disposition + code checks) | reranked evidence -> drop non-evidence text and cap budget -> structured answer (claims, citations, numbers, decision) -> code checks (schema, citations, numbers) -> answer, clarify, or decline.
- [PIPE-025](pipelines/PIPE-025.md) | Pipeline: feedback and monitoring (trace → score → route fix → versioned write) | trace each request -> score a sample with automatic checks -> find which stage failed -> send the fix to the right place (KB, memory, prompt, index) -> write only when confident, with version history -> alert when quality drifts.
- [PIPE-026](pipelines/PIPE-026.md) | Pipeline: end-to-end search plus a compiled wiki | fake sources with permissions -> ingest -> keyword+vector index over raw docs -> nightly job writes a wiki that cites raw doc IDs -> agent gets search + wiki -> answer with citations or say it can't be done.
- [PIPE-027](pipelines/PIPE-027.md) | Pipeline: parsing and chunking (layout, structure, searchable coverage) | file -> parser chosen by format, keeping layout, reading order and page positions -> remove headers, footers and hidden injected text -> chunk by structure (a section, a slide, or a table row with its header) -> check token limits -> embed with context, like the heading at the front -> count how many chunks per document are searchable.
- [PIPE-028](pipelines/PIPE-028.md) | Pipeline: enrichment and entity resolution | pull out names using a fixed ontology -> clean up names and match aliases -> shortlist about 10 likely matches per record with vector search -> score each pair -> merge automatically, send to a person, or create a new entity -> one writer saves to the graph, keeping each fact's source.
